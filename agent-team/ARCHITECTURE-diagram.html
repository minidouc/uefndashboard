Règles anti context-rot (Flash)

  • Black box : on partage l'output, jamais le raisonnement ni le transcript.
  • ≤ 4000 tokens par handoff ; au-delà → fichier référencé par son nom.
  • Faits atomiques en JSON structuré, zéro prose.
  • golden_example_ref = In-Context Distillation (1 exemple parfait).
  • Stable → prompt système ; transitoire → fichier d'état.
WP3 p.9 (context rot) · p.18 (black box) · p.22-24 (compaction) · p.34/p.45 (JSON schéma) · p.61 (stable vs transitoire).

D · Contrôle, anti-boucle & sécurisation MCP

ANTI-LOOP

  • Cap d'itérations / phase (dur).
  • Détection de delta : 2 tours = même payload → STOP.
  • before_tool_callback avant chaque dispatch.
  • Le garde-fou est du CODE hors du modèle.
WP1 p.12/p.35/p.38 · WP4 p.20 (repetitive/communication loops).

VALIDATEURS

  • Python coche schéma + acceptance.
  • Jamais d'auto-check par le Flash.
  • Error state (isError / 4xx / vide) = STOP, pas "comme si OK".
  • Generator-Critic sur les 3 pivots seulement.
WP2 p.29/p.30 · WP4 p.20 (error state ignoré).

MCP SÉCURISÉ

  • Allowlist + outils épinglés (mcp-inventory).
  • Tasks-level, pas API calls ; params courts.
  • 0 coordonnée calculée par le LLM → Python.
  • Least privilege · secrets hors contexte · output sanitizé.
WP2 p.9/p.15-19/p.26/p.41/p.43/p.44/p.47.

GATES HITL  4 points d'arrêt obligatoires avec l'utilisateur

1 · Validation du brief (Creative_Director) 2 · Validation du GDD (Game_Designer) 3 · Validation de l'architecture technique (Lead_Programmer) 4 · Avant TOUTE écriture destructrice dans Unreal
WP1 p.26 · WP2 p.36/p.43 · WP5 p.14/p.18. Ne jamais se fier au flag destructiveHint du serveur (WP2 p.27).
